# 최종 파이프라인 상세 (newbase-v22ens3)

README 의 요약을 학습 설정, 추론 순서, 패키지가 만들어진 과정까지 풀어 쓴 문서입니다.
수치는 각 학습 폴더의 `config.json`·학습 로그, 제출 기록, 대회 때 남긴 분석 노트에서 옮겼습니다.

## 1. 전체 흐름

```
공개 정사영상 3,950장면 ──► 합성기(synth.py) ──► 학습 스트림(무한, 배치 번호로 결정적)
          │                                          │
          └─► v2 모델 ─► 실배경 오탐 채굴 4,667장 ───┘ (음성의 20%)

학습: v4_r34 (판정) · v19_d3 → v22p, v22p_s2 → v26mk2 (마스크)
2차 분류기: v4 가 속는 표본(실제 해안 음성 + 합성/실측 양성)의 DINOv2 특징 → MLP

추론(패치 1장):
  v4 존재 확률(8방향) ─┬─ ≥ 0.9 ────────────────────────────► 양성 후보
                      ├─ 0.7~0.9 → v19_d3 확률 ≥ 0.9 화소 ≥ 50 ─► 양성 후보 (구제)
                      └─ 그 밖 ──────────────────────────────► 음성(빈 마스크)
  양성 후보 → 2차 분류기 p < τ 이면 음성
  마스크 = (v22p + v22p_s2 + v26mk2)/3 ≥ 0.35, 50화소 미만이면 56화소로 채움
```

## 2. 학습 데이터

합성 설정은 `src/synth.py` 의 `cfg_v4()` 와 `cfg_v26()` 입니다. 주요 값은 아래와 같습니다.

| 항목 | v4 레시피 | v26 레시피 (v26mk2 만) |
|---|---|---|
| 양성 비율 | 0.64 | 0.64 |
| 집적대 | 띠 길이 30~260 px · 폭 3~18 px (확률 0.65), 덩어리 반경 5~26 px, 패치당 1~3개 | 같음 |
| 작은 양성(tiny) | 0.12 | 0 |
| 렌더링 | 4배 초해상, 정답 = 피복률 ≥ 0.5, PSF σ 0.45~0.95 | 같음 |
| 팔레트 | 흰 0.38 · 회 0.18 · 청 0.11 · 녹 0.09 · 검정 0.06 · 기타 | 같음 |
| 색 구성 | 무채색만 25% / 유채색 5~45% 50% / 기본 25%, 채도 ×0.3~1.0 | 같음 |
| 센서 흉내 | 색 번짐 σ 0.3~2.5 (0.7), JPEG q 70~95 (0.3), 위성 룩 (0.6), 잡음 σ 0~8 | 같음 |
| 하드 네거티브 확률 | 0.6 | 0.7 |
| 하드 네거티브 종류 | 포말 0.28 · 자갈 0.25 · 해조 0.17 · 물고임 0.12 · 부표 0.18 | 흩어진 조각 0.5 · 포말 0.14 · 자갈 0.12 · 해조 0.09 · 물고임 0.06 · 부표 0.09 |
| 채굴 음성 비중 | 0.2 | 0.2 |

- 하드 네거티브는 양성 여부를 정하기 전에 그립니다. 그래서 v26 의 흩어진 조각(6~40자리, 서로 8 px 이상 떨어짐)은 양성 패치에도 정답 없이 깔립니다.
- 학습 표본에는 흑백(0.2)·색조·채도 흔들기(0.5)를 더합니다. 검증셋에는 넣지 않습니다.
- 학습 스트림의 난수는 (시드, 전역 배치 번호, 배치 내 위치)로 정해집니다. 워커 수를 바꾸거나 `--resume` 으로 이어도 같은 배치가 나옵니다.
- 현재 `synth.py` 로 만든 설정 문자열이 다섯 학습 폴더의 `config.json` 에 기록된 값과 모든 항목에서 같음을 확인했습니다. 이후에 추가된 항목은 기본값이 꺼져 있어 출력과 난수 흐름을 바꾸지 않습니다.

## 3. 모델별 학습 설정

| 이름 | 역할 | 구조·입력 | 초기값 | 스텝 | 배치 | lr | 시드 | 양성 가중 / β | EMA | 합성 검증 최고 | 학습 시간 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `v4_r34` | 1차 판정 | U-Net ResNet-34, 512 (2배 확대) | ImageNet | 20,000 | 24 | 3e-4 | 0 | 3 / 1 | 없음 | 0.8400 (step 17,000) | 118분 |
| `v19_d3` | 구제·초기값 | 얼린 DINOv3 ViT-L/16, 토큰 32 (512) | — | 6,000 | 24 | 3e-4 | 0 | 3 / 1 | 0.999 | 0.8686 (6,000) | 123분 |
| `v22p` | 마스크 1 | 토큰 48 (768) + 위치별 항 64 + AnyUp | v19_d3 (부분) | 4,000 | 12 | 1e-4 | 1 | 1 / 0.8 | 0.999 | 0.8910 (4,000) | 143분 |
| `v22p_s2` | 마스크 2 | v22p 와 같음 | v19_d3 (부분) | 1,500 | 12 | 1e-4 | 2 | 1 / 0.8 | 0.999 | 0.8946 (1,500) | 56분 |
| `v26mk2` | 마스크 3 | v22p 와 같음, 레시피 v26 | v22p_s2 | 1,500 | 12 | 1e-4 | 12 | 1 / 0.8 | 0.999 | 0.9164 (1,500) | 55분 |

- 학습 시간은 RTX A6000 1장에서 학습 로그의 경과 시간입니다.
- 합성 검증 점수는 같은 레시피 안에서 체크포인트를 고르는 데만 썼습니다. Public 순서를 예측하지 못했고, `v26mk2` 는 검증셋 구성이 달라(v26 레시피 기본 합성 1,000장) 다른 행과 비교할 수 없습니다.
- 공통: AdamW(weight decay 1e-4), OneCycle(5% 워밍업). 인코더·어댑터 쪽 lr 은 0.3배입니다. VFM 모델은 bfloat16 autocast, U-Net 은 float16 autocast 로 학습했습니다.
- `v4_r34` 의 `config.json` 에는 EMA 항목이 없습니다. 이 모델을 학습한 9/28 에는 `train.py` 에 EMA 옵션이 아직 없었습니다. 지금 `train.py` 의 기본값(EMA 0)으로 같은 명령을 돌리면 같은 설정입니다.
- 부분 초기화(`--init_partial`)는 이름·모양이 같은 가중치만 불러오고, 새로 생긴 위치별 항과 AnyUp 융합층은 0으로 시작합니다. 그래서 학습 시작 시점의 출력은 `v19_d3` 와 같습니다.
- 제출에 쓴 체크포인트: `v4_r34` 는 검증 최고인 `weights_fp16.pt`(step 17,000), 나머지는 마지막 스텝의 `weights_step<N>.pt` 입니다.

## 4. 2차 분류기

- **특징**: DINOv2 ViT-B/14 reg4 를 448 입력으로 얼려 쓰고, 원본과 좌우 반전의 평균으로 [CLS ‖ 패치 토큰 평균 ‖ v4 마스크 확률로 가중한 패치 토큰 평균] (2,304차원)을 뽑습니다. 여기에 1차 스칼라 4개(존재 확률 logit, 마스크 면적의 log1p, 최대 확률, 0.4 이상 화소의 평균 확률)를 붙여 2,308차원입니다.
- **표본**: 2차 분류기는 1차 양성만 보므로, 음성은 v4 존재 확률 ≥ 0.25, 합성 양성은 ≥ 0.4 인 것만 남겼습니다.

| 출처 | 라벨 | 입력 → 남은 수 |
|---|---|---|
| v4 2차 채굴 크롭 (원본·위성 룩·크롭 스트레치) | 음성 | 11,722 → 11,670 |
| v2 채굴 크롭 | 음성 | 4,667 → 706 |
| 네덜란드 PDOK 갯벌 (원본·위성 룩·스트레치) | 음성 | 10,512 → 3,141 |
| AI-Hub 71363 태안 드론 타일 (0.3 m) | 음성 | 9,174 → 3,332 |
| 합성 혼동물 (조개 띠·포말·자갈·해조·물고임·부표만) | 음성 | 9,000 → 2,520 |
| 합성 집적대 (v4 레시피) | 양성 | 7,634 → 6,824 |
| AI-Hub 506 조각으로 채운 합성 집적대 | 양성 | 3,401 → 2,901 |
| AI-Hub 71363 태안 실측 쓰레기 타일 | 양성 | 145 → 145 |

- **헤드**: MLP 2,308 → 512 → 128 → 1 (GELU, dropout 0.2·0.1). 입력은 학습 분할 평균·표준편차로 정규화하고 특징 잡음 σ 0.05 를 더했습니다. AdamW lr 1e-3, 40 에폭, 양성 가중 = 음성 수 / 양성 수.
- **분할과 임계**: 장면(그룹) 이름의 crc32 로 20%를 검증에 뺐습니다. 검증 양성 99.5%를 유지하는 τ = 6.136577e-07 을 썼습니다. 이때 로컬 검증에서 실제 음성의 87.1%를 거르고, 태안 실측 양성 37개는 모두 유지했습니다.
- **Public 에서의 효과**: 이 분류기를 처음 넣은 v16a 는 Public 오탐 30개 중 정확히 1개만 거르고 정탐은 잃지 않았습니다. 로컬 실제 음성과 Public 음성은 분포가 달랐습니다. 최종까지 남겨 둔 것은 정탐 손실이 없었기 때문입니다.

## 5. 추론 (`submission/predict.ipynb`)

노트북은 `assets/config.json` 과 `assets/model/` 만 읽고 네트워크 없이 돕니다. 채점 서버에는 OpenCV·SciPy 가 없어서 추론 코드는 NumPy·PyTorch·timm·smp·Pillow 만 씁니다(`submission/requirements.txt`).

1. `AIF_INPUT_DIR/patches.csv` 의 id 목록을 읽습니다. 중복 id 는 순서를 지켜 지웁니다.
2. 멤버 5개와 2차 분류기를 GPU 로 올립니다. 시험 추론이 실패하면 CPU 로 바꿉니다.
3. 4개 셀로 나눠 배치 8장씩 처리합니다.
   - 판정 경로: `presence_weight > 0` 인 멤버(v4)로 8방향 존재 확률과 v4 자체 마스크를 계산합니다(`gate_tta: d4`, 항상 고정).
   - 구제 경로: 존재 0.7~0.9 인 패치만 `rescue_weight > 0` 인 멤버(v19_d3)로 8방향 확률을 계산합니다.
   - 마스크 경로: `mask_weight > 0` 인 멤버 3개의 확률을 가중 평균합니다. 시간 가드가 이 경로의 TTA 만 줄일 수 있습니다.
   - `decide()` 로 양성·음성과 마스크를 정하고, 양성만 2차 분류기에 넣어 p < τ 면 빈 마스크로 바꿉니다.
4. 모든 행을 RLE 로 바꾼 뒤 주최 측 거부 규칙(정수·짝수 개·길이 ≥ 1·범위)을 스스로 다시 검사하고 저장합니다. 1~49화소 마스크는 빈 문자열로 냅니다.

`config.json` 의 주요 항목:

| 키 | 값 | 뜻 |
|---|---|---|
| `members[0]` | Unet resnet34, presence_weight 1 | 1차 판정 (v4_r34) |
| `members[1..3]` | VFM, mask_weight 0.333333 | 마스크 3개 (v22p, v22p_s2, v26mk2) |
| `members[4]` | VFM, rescue_weight 1 | 구제 판단 전용 (v19_d3) |
| `presence_thr` | 0.9 | 1차 판정 임계 |
| `rescue` | lo 0.7, t 0.9, n 50 | 구제 규칙 |
| `verifier.tau` | 6.136577e-07 | 2차 분류기 임계 |
| `mask_thr` | 0.35 | 마스크 임계 |
| `inflate_to` | 56 | 50화소 미만 마스크를 채울 크기 |
| `tta`, `gate_tta` | d4, d4 | 마스크·판정 TTA |
| `batch`, `fp16`, `time_budget_s` | 8, true, 5700 | 배치, 반정밀도, 추론 시간 예산 |

`src/postproc.py` 는 학습 때 임계 탐색에 쓴 결정 규칙이고, 노트북의 `decide()` 는 여기에 구제 규칙(`rprob`)을 더한 최종판입니다.

로컬 기록: 합성 평가셋 300장에서 이 패키지는 양성 100장을 냈고 A6000 에서 총 706.8초가 걸렸습니다. 직전 구성(v22pens)과 양성 집합이 같았고, 로컬 점수는 0.8917 → 0.8920, 집적대만 있는 셋의 형상 점수는 0.929 → 0.931 이었습니다.

## 6. 패키지가 만들어진 순서

대회 때는 직전 최고 패키지에서 판정이나 마스크 중 하나만 바꾼 패키지를 만들어 Public 으로 비교했습니다. 최종 패키지의 계보는 아래와 같습니다. 각 단계의 조립 스크립트는 이전 패키지가 있어야 돌아가서 저장소에는 넣지 않았고, `scripts/make_package.py` 가 그 결과(최종 config.json)에 가중치만 채웁니다.

| 패키지 | 판정 | 마스크 | Public |
|---|---|---|---|
| v4 | v4_r34 ≥ 0.4 | v4_r34 자체 | 0.7732 |
| v13a | 같음 | 큰 CNN 백본 3개 평균 (0.35) | 0.7861 |
| v16a | + 2차 분류기 | 같음 | 0.7898 |
| v18t90 | 임계 0.4 → 0.9 | 같음 | 0.8126 |
| v19t90 | 같음 | v19_d3 단독 | 0.8161 |
| v21r70 | + 구제 규칙 (v19_d3) | 같음 | 0.8172 |
| v22pens | 같음 | v22p + v22p_s2 평균 | 0.8287 |
| **v22ens3** | 같음 | v22p + v22p_s2 + v26mk2 평균 | **0.8321** |

판정이 같은 두 패키지의 점수 차 × 2 가 형상 점수 차입니다. 예를 들어 v22pens → v22ens3 은 +0.0033 이므로 형상 점수가 0.7915 → 0.7981 로 올랐습니다.

## 7. 남은 병목

Public 기준 최종 판정은 정탐 124, 오탐 22, 미탐 0 이었습니다. 판정만 완벽했다면 지금 마스크로 약 0.899 였습니다.
남은 오탐은 판정 모델·DINOv2·DINOv3 가 모두 쓰레기로 확신하는 패치였고, 실제 해안 음성이나 생성 혼동물로 학습한 분류기도 이 패치들을 거의 거르지 못했습니다.
'집적대를 이루지 않은 흩어진 조각은 음성'이라는 가설로 판정 모델을 다시 학습하면(v26b) 오탐은 줄었지만 같은 비율로 정탐도 잃었습니다. 같은 가설을 마스크에만 적용한 `v26mk2` 는 앙상블에서 도움이 됐습니다.
평가 영상과 같은 센서·지역의 라벨, 특히 흩어진 쓰레기와 정답에서 빠지는 혼동물의 실제 예가 있었다면 판정 쪽을 더 밀 수 있었을 것입니다.
